# FFXIV 任务树 · Quest Tree

最终幻想14（FFXIV）**全任务依赖树** —— 把每个任务的前置任务、后续任务、主分类、子分类、所属地区、NPC、版本等信息可视化出来。中 / 英 / 日 三语，可缩放、可筛选、可搜索跳转，主线剧情固定在画面中央的中轴线上。

A trilingual (中文 / English / 日本語), zoomable dependency graph of **every** FINAL FANTASY XIV quest, with the main scenario pinned to the central spine.

```
5377 个任务   ·   5213 条前置依赖   ·   949 个依赖层级   ·   0 个环
```

## 1. 功能

| 需求 | 实现 |
| --- | --- |
| 抓取所有任务及其信息 | **5 377** 个任务：等级、变更版本、资料片、所属地区、主分类、子分类、职业限制、开始/结束 NPC、坐标、经验/金币、Lodestone 链接 |
| 清晰展现前置 / 后续 | 分层有向无环图；选中任务时高亮其祖先与后代；"与/或" 前置条件有区分标注 |
| 缩放 scope | 滚轮缩放（围绕光标）、拖拽平移、适应窗口、双击聚焦、一键回到主线 |
| 主分类 / 子分类筛选 | 资料片 → 任务大类 → 主分类 → 子分类 四级联动筛选，带数量统计与快捷预设 |
| 搜索任务并跳转 | 三语搜索（支持忽略空格/标点的模糊匹配），键盘 ↑↓/Enter 操作，自动清除筛选并飞向目标；**`Ctrl+K` / `⌘K` / `/` 随时聚焦搜索框**（正在输入框里打字时 `/` 不抢键），框内侧显示当前平台的快捷键提示；**本地记录最近查看的 5 个任务**（存的是任务 id，聚焦空框即列出，可点回、单条删除或一键清空） |
| 右键查看依赖 | 右键任意任务 → 「查看前置依赖 / 查看后续任务 / 以此为中心」；依赖视图只展示该任务链接到的全部前序（或后续）任务，顶部横幅提示状态并可一键退出 |
| 把主线放中心 | 所有主线任务 lane ≈ 0（实测主线平均偏离中轴 0.4 lane，其余任务 104 lane） |
| 现代美观的 FF14 风格 | 深色鎏金 / 日间两套扁平主题（右上角一键切换，无渐变），官方任务类型图标、金色描边面板 |
| 中英日三语 | UI 三语 + 数据三语，语言选择持久化；首次访问按浏览器语言列表自动选择（`navigator.languages` → `<html lang>`），不支持的语言（de / ko / fr …）回落到英文 |
| Vercel 部署 | 纯静态产物 + `vercel.json`，无需任何服务端 |

**其它细节**

- 每个节点是一个**菱形**，外框颜色 = 任务大类。**不论当前视图有多少个任务，节点永远只有菱形，绝不会把任务图标叠在节点上** —— 官方任务图标只出现在图例和悬停卡片里（悬停卡片在视图 ≤ 50 个任务时带图标）。
- **画布上一次位图都不画**（`drawImage` 恒为 0 次）：5000+ 节点的全量视图和 40 个节点的子分类视图走的是同一条纯菱形路径，拖动缩放才稳。图例会在视图 ≤ 50 个任务时才列出三个类型图标，悬停卡片的图标同样遵守这个阈值。
- 名称标签也分级：放得够大才显示，主线任务优先于支线。
- **依赖视图从"局部特写"开始**：进入 `/pre` `/post`（或右键查看依赖）时，相机把选中任务放在链条的末端（前置视图放在画面右侧 72%、后续视图放在左侧 28%），缩放按"一屏大约 8 个层级"计算，随窗口宽度自适应（上限为全局最大缩放 3.2）。剩下的祖先由用户自己拖动查看，不再一进来就把整条链缩成一张全览图。搜索跳转仍然把任务放在画面正中。
- 相机请求（`nonce`）只生效一次：**切换侧栏筛选会重新适应窗口，而不会把镜头拽回上一次搜索的任务**。
- **分享链接用任务 id**：横幅里「复制链接」写出 `/pre/69477`、`/post/69477` —— 短、没有百分号转义、并且与语言无关（中文任务名放进 URL 又长又只有中文用户看得懂）。旧的名字链接仍然有效：`/pre/<中文名>`、`/pre/<English name>`、`/pre/<日本語名>` 与旧的 `?id=` 消歧参数都能打开，只是新链接不再需要它们。`/pre/99999999` 这种不存在的 id 会给出提示，而不是一片空白画布。
- **进站语言**：`index.html` 里有一段首屏前执行的脚本，按「上次选择 → `navigator.languages` → 都不支持则英文」决定 `<html lang>`；`src/i18n.ts` 的 `chooseLang()` 用同一套规则（先浏览器语言，再读回该属性，最后英文），因此屏幕阅读器、SEO 和界面语言不会互相打架。
- 侧栏含「仅显示主线任务」「显示任务锁（额外解锁条件）」开关。**依赖视图会忽略侧栏筛选**（否则祖先链会被截断），横幅里写明了这一点。
- 详情面板给出「各语言名称」对照表，并保留 Lodestone 官方链接；底部同样有「查看前置依赖 / 查看后续任务」按钮。
- 图例分两部分：任务大类配色 + 三种任务类型图标；只列出当前视图中真实出现的任务大类。
- **最近查看**存在 `localStorage: xiv-quest-tree:recent-quests`（最多 5 个，最新在前）：记录的是**点进去的那个任务 id**，而不是搜索词 —— 下次从列表里点回去就直接跳转，而且名字永远跟着当前界面语言显示（数据集重建后失效的 id 会自动从列表里消失）。空框聚焦即列出，每条可以单独移除，标题右侧可一键清空。搜索结果里被当前筛选挡掉的任务会标一个小徽标（「筛选外」/ filtered out / 絞り込み外）。
- **站点图标**（浏览器标签页 / 收藏 / iOS 主屏）不是游戏内的任务标记 —— 那些标记在画布上表示「主线 / 支线 / 职业」，拿来当站点图标会被读成一种任务类型。用的是本站自己的节点造型：`public/favicon.svg` 里三个扁平图形（底色圆角方块 + 金色菱形环 + 亮金核心），配色直接取自 UI 的 `--bg` / `--gold` / `--gold-bright`，`npm test` 会断言三者始终一致、且图形里没有渐变。

## 2. 数据来源

> 说明：任务书里给的中文 wiki（`ff14.huijiwiki.com`）在本机 **无法访问** —— 它对包括 API 在内的所有路径都返回 Cloudflare 托管质询（`403 / 请稍候…`，基于 IP 信誉，与 User-Agent 无关）。因此改用**与 wiki 同源的官方游戏数据表**，信息量更大、结构更可靠，并额外用 Lodestone 与沙之家文本库做了交叉验证。

| 来源 | 用途 | 说明 |
| --- | --- | --- |
| [thewakingsands/ffxiv-datamining-cn](https://github.com/thewakingsands/ffxiv-datamining-cn) | **中文名**、中文 NPC / 地区 / 分类名 | 国服客户端数据表导出；XIVAPI 完全没有中文数据（`Name_cn` 全为 null） |
| [XIVAPI v2](https://v2.xivapi.com/) | 英文 / 日文 / 德文 / 法文名、任务分类树、奖励、图标 | 仅 v2 与当前游戏版本一致 |
| [XIVAPI v1](https://xivapi.com/) | 「变更版本」patch 号 | **v1 数据已过期**（行号错位、止于任务 70723），只有 patch 号仍可靠，故仅取该列 |
| [Lodestone 任务数据库](https://eu.finalfantasyxiv.com/lodestone/playguide/db/quest/) | 官方英文链接、开始 NPC 坐标 | 共抓取 **5 149** 个任务页（列表 103 页 + 详情页），0 失败 |
| [沙之家 strings](https://strings.ffcafe.cn/) | **独立三语校验** | 抽样 69 个任务按 row id 比对中/英/日名称，**100% 一致** |
| 游戏图标表（`ui/icon/0710xx`） | 任务类型图标 | 通过 XIVAPI 图片 CDN 取官方 PNG，见下文 |

### 任务类型图标

wiki 本身抓不到，但它展示的任务图标就是游戏内的官方素材 —— 所以直接从游戏图标表取，并且**用数据校验过**：

- `EventIconType` 表给出每种类型的图标，而某个类型对应的**图形标记**就紧挨着它的文字贴图（`NpcIconAvailable` 是 `71200 / 71220 / 71340` 这种烫金 "AVAILABLE … QUEST" 字样，标记本身是下一个号）。
- 交叉验证：**全部 1050 个主线任务都带主线标记值 `EventIconType 3`**，无例外；反过来 `3` 还多包含 94 个日志里没有归类、但确实串在主线链上的任务（如「超越幻想，究极神兵」「伊修加德保卫战」）。
- 因为节点颜色用的是游戏内置的 `JournalSection`，图标也按同一维度取，保证**图标与配色永远一致**：主线 → `71201`，职业任务 → `71341`，其余 → `71221`。
- 三个 PNG 合计 **39 kB**，放在 `public/icons/`，只作为图例与悬停卡片的 `<img>` 使用，因此不进画布、不参与逐帧渲染；`tools/fetch-icons.mjs` 会重新下载并测量每个图标的 alpha 内容框。

图标长什么样没法在无浏览器的环境里直接看，所以 `tools/icon-view.mjs` 会把任意图标解码成 ASCII 打印出来（`npm run icons:view 71221`），用来确认取到的是"！"标记而不是文字贴图 —— 上面那个结论就是这么得出来的。

数据以任务 ID 为主键对齐。所有名称都会清理 FFXIV 的私用区图标字形（`U+E000–U+F8FF`）与零宽字符 —— 例如「重现“女王之刃”」在原始数据里是 `\uE0BF␠重现“女王之刃”`。

### 分类体系说明

站点使用游戏内置的日志分类，正是 wiki 上「主分类 / 子分类」的来源：

```
JournalSection（任务大类） → JournalCategory（主分类） → JournalGenre（子分类）
例如：支线任务 → 武器强化支线任务 → 天佑女王
```

同时修正了两个容易踩的坑：

- `JournalSection` 的 `0` 是**真实主线章节**（重生～晓月），而 184 个 ARR 职业任务在游戏数据里没有分类。之前它们会被错误归入主线；现在使用哨兵值 `-1`（无分类）区分，主线数量为正确的 **1 050**。
- `ExVersion` 的 `0` 是「重生之境」，不是空值。

## 3. 快速开始

```bash
npm install --ignore-scripts   # 见下方说明
npm run dev                    # http://localhost:5173
npm run build                  # 产出 dist/
npm run preview                # 本地预览 dist/
```

> `--ignore-scripts`：本仓库的依赖（React / Vite / esbuild）不需要构建脚本，可避免在受限环境中安装失败。正常机器上直接 `npm install` 也可以。

### 数据流水线

仓库里已包含构建好的 `public/data/quests.json`（2.5 MB），**开箱即用**。需要重新抓取时：

```bash

npm run data:xivapi     # 抓 XIVAPI v2（+ v1 的 patch 列），带缓存
npm run data:lodestone  # 抓 5 149 个 Lodestone 任务页，可断点续抓
npm run data:build      # 合并为 public/data/quests.json
npm run data:all        # 以上全部
```

### 验证

```bash
npm run typecheck       # 严格 TypeScript 检查
npm test                # 数据 / 分类 / 筛选 / 搜索 / 布局 / 相机取景 / 配色对比度 全量断言
npm run verify:strings  # 与沙之家三语文本库交叉验证
npm run graph:ascii     # 在终端里以 ASCII 密度图检查布局形状
npm run test:dom        # 在 jsdom 里跑真实打包产物，像用户一样驱动界面
npm run icons:view 71221  # 把任意游戏图标解码成 ASCII 打印出来
npm run icons:view public/favicon-32.png  # 也可以直接解码本地 PNG
npm run icons:site      # 从 favicon.svg 的几何重新生成 favicon-32.png / apple-touch-icon.png
```

`npm run icons:site` 不依赖任何库：PNG 就是 zlib 外面套一层容器（Node 自带 zlib），图形是三个扁平菱形，于是直接按「点在不在形状里」在 4 倍分辨率上采样再降采样，抗锯齿边缘就是这么来的。`favicon-32.png` 是圆角方块（标签页里好看），`apple-touch-icon.png` 是满幅方块（iOS 会自己套圆角，预先切角反而会露出黑角）。

`npm run graph:ascii all 186 100` 会打印整张图的形状；传任务大类 id 可只看某一部分，加 `--vertical` 可切换主轴线方向。

`npm test` 里的「dependency view framing」一节直接对 `src/graph/camera.ts` 断言：任意窗口宽度下取景都是 8 个层级、缩放不会越出全局上下限、锚点确实把任务放在 72% / 28% 处，并抽样 60 个真实任务验证 `/pre` 视图打开时紧邻的祖先层级确实留在画面内。

`npm run test:dom` 会用 `dist-test/app.js`（IIFE 打包）在 jsdom 里真实启动整个应用，然后：勾选「天佑女王」子分类、用三语搜索并跳转、验证快捷键（`Ctrl+K` 与 `/` 聚焦、输入框内 `/` 不被拦截）、最近查看任务的记录 / 点回 / 单条删除 / 清空、点前置任务芯片导航、切换三种语言、套用主线预设、用 `/pre/<名字>`、`/pre/<id>` 与失效链接分别导航，最后断言详情面板里的版本 / 地区 / 分类 / NPC 坐标 / 三语名称 / Lodestone 链接，以及「复制链接」给出的确实是 `/pre/69477` 这种 id 链接。画布用一份**显式的 2D context 模拟**（只实现真正用到的方法），因此渲染器一旦调用不存在的 API 就会直接失败 —— 这条测试还会断言画布上 `drawImage` 恒为 0 次（节点永远只是菱形），并且全程 0 个未捕获异常、0 个 React 报错。

## 4. 布局算法

`src/graph/layout.ts` —— 输入当前可见任务集合，输出坐标：

1. **rank（依赖轴）**：按「从无前置任务起的最长路径」给每个任务分层，前置在左、后续在右。
2. **lane（纵向位置）**：
   - 主线任务（`JournalSection` 0 / 1）固定在中轴 `lane ≈ 0`；
   - 其余任务的期望位置 = **所有可见前置任务 lane 的重心**，因此任务链保持笔直、不会左右抖动；
   - 同层内按期望位置排序后向中轴两侧依次外扩，保证最小间距。
3. **纵向压缩**：约 900 个任务既无前置也无后续（季节活动、友好部族日常等）。它们全部落在第 0 层，会把画布撑成一根几乎空心的长条。因此对**不承载任何依赖边**的 lane 采用紧凑排布，使画布宽高比接近 16:9。

实测：5 377 个节点布局耗时约 **36 ms**，无坐标重叠，无环；筛选后重新布局同样即时完成。因为布局是**针对当前可见子图**计算的，筛到「天佑女王」这类小集合时会自动收紧成清晰的小树。

## 7. 已知限制

- **4 个任务**（67080、67081、67678、67680）只有国服文本，国际服数据表里名称为空，因此英/日名称回退显示中文名。
- **692 个任务**没有 patch 号：XIVAPI v1 的快照止于任务 70723，而 v2 的新 schema 已移除该列；这些任务在界面上不显示版本徽章。
- Lodestone 不提供前置任务信息（只有官方 wiki 与游戏数据表有），所以依赖关系来自游戏数据表；Lodestone 用于官方链接、坐标与交叉校验。
- 简体中文之外的繁体（`tc`）未收录：沙之家的 `tc` 列存在错位，不可信。
- 全量视图有 5 377 个节点，缩小到整屏时必然密集；建议配合筛选或搜索使用。这是数据规模的固有限制，不是渲染问题。
